## PHASE 0 — Аудит и стабилизация · 2026-09-23

### Добавлено
- `docs/CURRENT_STATE.md` — аудит существующего кода: стек, модули, схема БД, API, найденные проблемы (критические, важные, техдолг), соответствие целевым требованиям.
- `docs/IMPLEMENTATION_PLAN.md` — фазы 0–13 с задачами и статусами, приёмочный сценарий из 24 шагов.
- **Инфраструктура тестов** (её не было вообще): vitest для модульных тестов, vitest + supertest для интеграционных, отдельная одноразовая база `gsi_test`, сервис `test` в docker-compose с профилем `test`.
  - модульные: разбор CSV/XLSX и приведение типов при импорте, запись CSV при выгрузке, машина статусов заявки;
  - интеграционные: аутентификация и обращение с токенами, изоляция филиалов и проверка ролей (RLS), полный жизненный цикл заявки от создания клиента до выпуска отчёта и публичной верификации.
- ESLint для backend.
- Заголовки безопасности (`helmet`) и ограничение частоты запросов: общий бюджет на API и отдельный, жёсткий, на вход в систему.
- Идентификатор запроса (`X-Request-Id`), сквозной в логах и в теле ошибки.
- Структурированное логирование запросов (JSON в production, читаемый вид в разработке).
- Health-проверки: `/api/health/live`, `/api/health/ready`, `/api/health` с проверкой БД и объектного хранилища.

### Изменено
- Единый обработчик ошибок: пользователь больше не видит `500 Internal Server Error` со служебными деталями — только понятное сообщение и ссылочный идентификатор, по которому ошибку можно найти в логе. Обработка ошибок PostgreSQL сохранена и встроена в общий обработчик.
- Демо-данные отделены от эталонных: тесты и разработка могут поднимать базу без годовой истории счетов (`SEED_DEMO_VOLUME=false`), курсы валют засеваются всегда.
- Засев демо-данных в production логирует явное предупреждение.

### Известные ограничения на конец фазы
- Иерархии «организация → страна → офис» и granular permissions ещё нет — это PHASE 1.
- Журнала аудита ещё нет — PHASE 1.
- Пагинации в списках ещё нет — PHASE 3 и PHASE 12.
